# RoboCompanion — конспект занятия №1

**Тема:** настройка среды разработки, Arduino UNO R3, PlatformIO и первая прошивка.

## 1. Цель проекта

RoboCompanion — проект автономного робота, который в дальнейшем будет работать с датчиками и исполнительными устройствами.

Планируемая архитектура:

- **Arduino UNO R3** — управляет подключёнными датчиками, светодиодами, моторами и другими компонентами.
- **C++** — язык прошивки Arduino.
- **Python** — в дальнейшем будет использоваться для разработки логики и интерфейсов управления на компьютере.
- **PlatformIO** — среда для сборки и загрузки прошивок Arduino.
- **VS Code** — редактор кода, в котором ведётся разработка.

Важно: Arduino UNO R3 не запускает обычные Python-программы самостоятельно. Прошивка на Arduino пишется на C++, а Python может взаимодействовать с платой через USB.

## 2. Установленная среда разработки

Используемые инструменты:

| Инструмент | Для чего нужен |
|---|---|
| VS Code | Редактирование кода и работа с проектом |
| PlatformIO | Сборка, загрузка и мониторинг Arduino |
| Python | Разработка управляющих программ |
| `.venv` | Виртуальное окружение Python |
| `pyserial` | Обмен данными между Python и Arduino через последовательный порт |
| Git (в будущем) | Контроль версий кода |

Для Python создано виртуальное окружение `.venv`, установлена библиотека `pyserial==3.5`, а зависимости сохранены в `requirements.txt`.

### Основные команды Python

Активировать виртуальное окружение в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установить зависимости проекта:

```powershell
python -m pip install -r requirements.txt
```

Посмотреть установленные пакеты:

```powershell
python -m pip freeze
```

Сохранить список зависимостей:

```powershell
python -m pip freeze > requirements.txt
```

## 3. Структура проекта PlatformIO

Основные файлы и папки:

```text
RoboCompanion/
│
├── .pio/
│   └── build/
│       └── uno/
│           ├── firmware.elf
│           └── firmware.hex
│
├── .vscode/
│
├── include/
│
├── lib/
│
├── src/
│   └── main.cpp
│
├── test/
│
├── .venv/
│
├── platformio.ini
└── requirements.txt
```

### Назначение элементов

**`src/main.cpp`**

Основной исходный код прошивки Arduino. Здесь описывается поведение робота.

**`platformio.ini`**

Конфигурация проекта PlatformIO. Сейчас используется следующая конфигурация:

```ini
[env:uno]
platform = atmelavr
board = uno
framework = arduino
```

Она означает:

- `env:uno` — имя окружения сборки;
- `platform = atmelavr` — платформа микроконтроллеров AVR;
- `board = uno` — целевая плата Arduino Uno;
- `framework = arduino` — используется Arduino Framework.

**`.pio/`**

Служебная папка PlatformIO. В ней находятся результаты сборки и другие файлы, необходимые инструментам разработки.

**`.vscode/`**

Настройки редактора VS Code для проекта.

**`include/`**

Заголовочные файлы проекта, если они понадобятся.

**`lib/`**

Библиотеки проекта.

**`test/`**

Папка для тестов, если мы будем добавлять их для прошивки или отдельных модулей.

**`.venv/`**

Виртуальное окружение Python. Оно не является частью прошивки Arduino.

**`requirements.txt`**

Список Python-зависимостей проекта.

### Важный вывод

`main.cpp` — исходный код.

`firmware.hex` — собранная прошивка, которую PlatformIO записывает в микроконтроллер.

Это разные вещи: Arduino не читает `main.cpp` напрямую.

## 4. Основные кнопки PlatformIO

В VS Code слева есть раздел PlatformIO, а внизу обычно доступны быстрые команды.

| Кнопка или действие | Назначение |
|---|---|
| **Build** — галочка | Собрать прошивку из исходного кода |
| **Upload** — стрелка вправо | Собрать прошивку и загрузить её в Arduino |
| **Clean** | Очистить файлы сборки на компьютере |
| **Serial Monitor** | Открыть последовательный монитор для обмена данными с Arduino |

В панели **Project Tasks** задачи обычно находятся в разделе:

```text
Project Tasks
└── uno
    └── General
        ├── Build
        ├── Upload
        └── Clean
```

Названия и расположение отдельных пунктов могут немного отличаться в зависимости от версии PlatformIO.

### Разница между Build, Upload и Clean

**Build**

Компилирует исходный код и создаёт новую прошивку на компьютере. Не записывает её в Arduino.

**Upload**

Собирает проект и записывает новую прошивку в память Arduino. Обычно предыдущая прошивка заменяется новой.

**Clean**

Удаляет результаты сборки на компьютере. Не удаляет прошивку, уже записанную в Arduino.

После `Clean` можно снова выполнить `Build` и `Upload`.

## 5. Как устроена программа Arduino

Программа Arduino обычно содержит две главные функции:

```cpp
void setup() {
    // Выполняется один раз при запуске платы
}

void loop() {
    // Выполняется многократно, пока плата включена
}
```

### `setup()`

Выполняется один раз после запуска или перезапуска платы.

Здесь настраиваются последовательный порт, пины и другие компоненты.

### `loop()`

Выполняется снова и снова. Здесь программа проверяет входящие команды, считывает датчики и управляет устройствами.

### Последовательный порт

```cpp
Serial.begin(9600);
```

Открывает последовательную связь на скорости 9600 бод.

```cpp
Serial.println("Hello!");
```

Отправляет сообщение в Serial Monitor. `println()` завершает строку символами окончания строки.

```cpp
Serial.available()
```

Показывает, есть ли принятые данные.

```cpp
Serial.read()
```

Читает один принятый символ.

```cpp
Serial.write()
```

Отправляет данные в последовательный порт.

## 6. Первая прошивка RoboCompanion

Первая программа умеет:

- сообщать о запуске;
- принимать команды с компьютера;
- отвечать на команду проверки связи;
- включать и выключать встроенный светодиод.

Основные команды:

| Команда | Действие | Ответ |
|---|---|---|
| `PING` | Проверка связи | `PONG` |
| `LED_ON` | Включить светодиод | `LED is ON` |
| `LED_OFF` | Выключить светодиод | `LED is OFF` |

При запуске программа отправляет:

```text
RoboCompanion ready!
```

### Как обрабатываются команды

1. Компьютер отправляет текст.
2. Arduino получает символы через `Serial.read()`.
3. Символы собираются в строку `command`.
4. Символ `\n` сообщает программе, что команда закончена.
5. Программа сравнивает строку с известными командами.
6. Arduino выполняет действие и отправляет ответ.
7. Строка команды очищается для следующего сообщения.

Например, если получена строка `PING`, программа отправляет `PONG`.

Если получена неизвестная команда, программа отправляет:

```text
Unknown command
```

Пустая строка тоже может приводить к этому ответу, потому что текущая версия программы отдельно не игнорирует пустые команды.

## 7. Serial Monitor

Serial Monitor нужен для проверки связи между компьютером и Arduino.

В нашем проекте используются параметры:

```text
Port: COM5
Baud rate: 9600
```

Номер COM-порта может измениться после переподключения платы. Если `COM5` больше не работает, нужно проверить, какой порт назначен Arduino.

### Как проверить связь

1. Откройте правильный проект в VS Code.
2. Откройте Serial Monitor через PlatformIO.
3. Убедитесь, что используется скорость 9600.
4. При необходимости нажмите RESET на плате.
5. Проверьте, появилось ли сообщение:

```text
RoboCompanion ready!
```

Затем отправьте команды:

```text
PING
LED_ON
LED_OFF
```

### Важный нюанс ввода

В нашем случае вводимые символы не отображались в терминале, но команды всё равно отправлялись. Это не обязательно означает неисправность.

Для текущей программы важно, чтобы отправленная команда завершалась символом новой строки `\n`. Если отправлять только текст без окончания строки, программа не перейдёт к обработке команды.

Если при нажатии Enter появляется `PONG`, значит, команда `PING` была успешно принята и обработана.

### Управление терминалом

- `Ctrl + C` — остановить запущенный Serial Monitor.
- `Ctrl + T` — открыть меню монитора, если эта комбинация поддерживается текущим терминалом.
- `Ctrl + H` после `Ctrl + T` — открыть справку по горячим клавишам монитора.

Не путайте Serial Monitor с обычным терминалом PowerShell. Это разные способы взаимодействия с компьютером.

## 8. Что произошло с проектами и почему это важно

Во время настройки возникла проблема: PlatformIO запускал задачи в папке `iot_station`, хотя мы работали над `RoboCompanion`.

Из-за этого можно было редактировать один `main.cpp`, а загружать прошивку из другого проекта.

### Правило на будущее

Перед нажатием Upload проверяйте:

1. Какая папка открыта в VS Code.
2. В каком `main.cpp` вы изменяете код.
3. Из какой папки запускается задача PlatformIO.
4. Какой COM-порт используется при загрузке.

Если код на плате не меняется, не нужно сразу переписывать программу или переустанавливать драйверы. Сначала проверьте, что открыт и загружается правильный проект.

В нашем случае после переключения на правильный проект сообщение `RoboCompanion ready!` появилось, а команды `PING`, `LED_ON` и `LED_OFF` заработали.

## 9. Как завершить работу и продолжить завтра

### Завершение работы

1. Остановить Serial Monitor сочетанием `Ctrl + C`.
2. Сохранить изменённые файлы сочетанием `Ctrl + S`.
3. Отключить USB-кабель от Arduino.
4. При желании закрыть VS Code.

Отдельно удалять прошивку не нужно.

### Возобновление работы

1. Подключить Arduino к USB.
2. Открыть VS Code.
3. Открыть правильную папку `RoboCompanion`.
4. Проверить `src/main.cpp` и `platformio.ini`.
5. Открыть Serial Monitor на актуальном COM-порту со скоростью 9600.
6. Проверить запуск и отправить `PING`.

Arduino автоматически запускает последнюю загруженную прошивку после подачи питания.
